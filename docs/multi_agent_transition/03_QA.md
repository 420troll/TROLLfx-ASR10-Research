## Investigation and required findings

1. **Artificial two-point caps:** `force_plugin/src/ASR10FXCollection.cpp` has `verified_points.size() == 2` control-registration assumption; `include/trollfx/es5510_factory_editor_v04.hpp` includes HALL `{40,41}`. Audit similar generated arrays, validation scripts, test assertions and limits imposed by packaging.
2. **Full-range original HALL:** 128 raw states / displayed 0–99, duplicate LCD values (raw 51 and 52 =>40), original Up/Down skip behavior; validated HALL GPR group `6E/5B/03/04/05`, initial raw52 and safe startup schedule boundary 12984. Compare current implementation to original OS evidence and actual VST2 callback -> scheduled GPR -> audio. Instrumented 0/99 tests are not proof of production host control completion. Original display->raw ambiguity and chunk migration are high-priority.
3. **Catalog/integration mismatch:** 594 documented descriptors vs 19 runtime-ready routes. Classify per parameter: documented in manual, OS captured, GPR group verified, integrated in production, actual VST2 measured, physical Force tested. Classify gap as obsolete artificial restriction, missing engineering, or genuinely missing research evidence. No fabricated 'ready' flags.
4. **DAMPING and DELAY failure analysis:** UI control change -> VST name/ID -> availability -> catalog point -> queued GPR group -> actual applied state -> audio delta with appropriate stimulus. High-frequency damping user reports no audible effect; delay time range too narrow. Determine precise cause, not just whether callbacks return success. For missing registers or unavailable original points mark blocked and report.
5. **State and concurrency hazards:** worker dual-runtime `ready_index`, shared status and request generations, stale background completion, A->B->A switch, old-effect writes to newly selected DSP, parameter dirty flags cleared before successful apply, queued vs applied mismatch and effect-state recall. Test fail-closed and durable saved chunk compatibility.
6. **Packaging traps:** checked-in `docs/ASR10_FORCE_DYNAMIC_EDITOR_V41_ARMV7_QEMU.json` historical result may incorrectly block/relabel candidate hashes in `build_release.py`; source digest may mix evidence and inputs. Verify exact binary, SDK, generated skins, 50-slot asset index and marker. No historical QEMU PASS on different binary.
7. **48 kHz runtime assumption:** `ES5510DSPBackend.cpp` forces `RateMode::Experimental48000` in both load paths; original processing ~29.76k / 44.1k contexts need explicit fidelity caveat. Do not change audio mode as a QA shortcut.
8. **ARM harness incident:** temporary Zig-built ARM harness crashed **before assertions**, with suspected hard-float argument ABI attributes mismatch. The live MPC plugin continued healthy. Reproduce only in disposable controlled harness, capture signal/ELF attributes, attribute product status INCONCLUSIVE until actually shown. QEMU unavailable for deployed candidate. Don't conflate host harness crash with plugin crash.
