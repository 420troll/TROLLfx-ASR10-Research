# ROM-01 HALL GPR reconciliation

## Finding

The 16 disputed registers are `0x90`–`0x9f`. They are absent from the selected HALL reload's 342 GPR/SPR commits, so a replay that starts with a zeroed register file reports them as mismatches. The private event trace shows these values were written earlier in the same OS boot, by `BOTH_COMMIT` host transactions while PA4 remained HALT. The HALL HALT/pipeline reset does not clear the GPR file. Replaying those prior writes before the selected HALL load reproduces all 192 manifest GPR values.

For `0x90`–`0x9e`, the last prior writes are event IDs 719, 721, …, 751 at ESP frame 382,949. `0x9f` has the last write at event 753, frame 382,950. All are halted host commits before the selected HALL load. Each disputed register has two recorded writes in the first 15 cases; `0x9f` has four. None is written during the selected HALL transaction.

The two fresh OS 3.53 captures have the same complete run-snapshot SHA-256 and the same GPR SHA-256; both match the manifest's GPR payload. Reconciliation against either event trace produces the same 16-address result. The value-bearing table records each expected manifest value, zero-baseline transaction value, full-history value, every write coordinate, and PA4 phase in a private output file. It is generated outside the repository with `tools/audio_validation/reconcile_hall_gpr.py`.

## Register role and replay correction

The active 89-word HALL program has no A/B/C/D operand references to `0x90`–`0x9f`, and these addresses have no host writes during the selected HALL transaction. Their differences are not DSP-generated by that active HALL program and do not indicate a GPR address decode error. The event history identifies them as retained, loader-populated GPR state; their more specific purpose as parameters or workspace is not established by the available evidence.

`tools/audio_validation/replay_hall.py` now seeds replay from the recorded prior GPR host commits and then applies the exact selected 342 GPR/SPR plus 89 instruction commits. The manifest and final-state checks remain strict. The resulting GPR state matches the manifest; the runner still stops before audio comparison because six SPR values remain unexplained. No expected values or write events are fabricated.

