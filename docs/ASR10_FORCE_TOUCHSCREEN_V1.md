# TROLLfx ASR-10 Force Touchscreen and Q-Link V1

## Implemented

The Force skin is authored in [`force_plugin/ui.json`](../force_plugin/ui.json) and generated by the inspected InMusic SDK into the tracked release candidate's `Plugin Skins/TUI.json` and `Q-Links.json`. It uses the SDK's supported 1280x628 content grid, cyan kit, charcoal background, and only its supported text, slider, knob, fader, switch, and empty widgets.

The browser exposes the 50 catalog slot numbers and original factory names in a selection menu. The plugin appends `[READY]` or `[UNAVAILABLE]` using the injected validated-package provider at plugin construction. Selecting the current effect displays a runtime value string with `PACKAGE REQUIRED`, `UNAVAILABLE`, `LOADING`, `LOAD FAILED`, `READY`, or `SELECTED`. These values come from provider/backend state; effect availability is not compiled into the labels. The provider must be installed before plugin creation for the initial selection labels to reflect it.

The `BROWSE` and `MIX` tabs map the SDK's Q-Link 1–5 to Wet/Dry, Input Gain, Output Gain, Factory Effect, and Bypass. Q-Link 6 (preset selection) and Q-Links 7–8 remain blank. `EDIT` only exposes the two verified BUS values for the selected HALL or ROM-02 effect; unknown controls are not declared. The numeric choices show the two experimentally verified adjacent values for each algorithm. The generic mapping adapter schedules the resulting GPR update at the active runtime's next DSP frame on the audio thread. No GPR data or proprietary package is embedded in this plugin or a preset.

Stable parameter IDs and values are included in the SDK framework's VST chunk state. Thus Force project/plugin state restores factory slot, wet/dry, gains, bypass, and verified BUS choices. User-named preset browsing, save/rename buttons, and preset-name display are not provided by the inspected JSON skin API; Force owns the host preset/project interaction. The plugin does not claim custom preset management.

## Controls and integration status

| Control | Binding | State |
|---|---|---|
| 50 effect browser | `effect_slot` | Functional; package status comes from the provider and backend |
| Wet/dry, input gain, output gain, bypass | `host_wet`, `host_input_gain`, `host_output_gain`, `host_bypass` | Functional through the existing DSP backend |
| HALL REVERB MIX BUS1/BUS2 | `hall_bus1`, `hall_bus2` | Functional for verified values 28 and 29 |
| 44KHZ REVERB MIX BUS1/BUS2 | `rom02_bus1`, `rom02_bus2` | Functional for verified values 25 and 26 |
| Other factory parameters | Not declared | Await Codex 1's verified metadata and runtime-safe mapping |
| Q-Link 6 preset selector | Empty | Host preset interaction is not a plugin parameter/action supported by this skin API |
| Stereo meters, DSP load, host rate display | Not exposed | SDK-generated UI schema has no read-only meter/display widget; no editable fake meter parameters were added |

The custom `FX Slot` value formatting reports a selected package's current backend state. The per-choice `[READY]`/`[UNAVAILABLE]` suffix is an availability snapshot taken at plugin construction. A provider that is injected after instantiation can be discovered by the existing backend during `prepare`, but the already-created choice labels will not be rewritten.

## Q-Link map

The SDK maps Q-Link columns from positions on the fixed 4x4 grid. The generated map was inspected after building:

| Tab | Q1 | Q2 | Q3 | Q4 | Q5 | Q6–Q8 |
|---|---|---|---|---|---|---|
| BROWSE | Wet/Dry | Input Gain | Output Gain | FX Slot | Bypass | Blank |
| MIX | Wet/Dry | Input Gain | Output Gain | FX Slot | Bypass | Blank |
| EDIT | HALL BUS1 | HALL BUS2 | ROM02 BUS1 | ROM02 BUS2 | Blank | Blank |

The effect visibility conditions show only the selected algorithm's controls. The generated editor grid places the HALL pair on Q1/Q2 and the ROM-02 pair on Q3/Q4 because the current fixed skin generator cannot bind effect-dependent parameters to the same Q-Link positions on one tab. Future manifest-driven parameter metadata can populate the same editor page/banks, but this initial fixed layout should be normalized when the host gains a supported shared dynamic Q-Link binding.

## State, callback, and preserved engine

The adapter only forwards changed, verified BUS choices after the selected package is active. Writes use `FactoryRuntime::setRegister` at the active runtime's processed DSP frame. This is frame-scheduled and bounded; the change does not assert the factory host's full smoothing/write cadence or click-free parameter transitions. The private-package audio smoke measured a nonzero output difference for the HALL BUS controls against the default settings (sum absolute stereo difference 4.0562439 over the exercised signal). ROM-02 BUS1's encoded write was accepted by the actual backend, but the same short deterministic signal produced zero measured output difference against its default; this is recorded as unverified audible response, not an equivalence or a control failure. The runtime reports the mapped register write accepted, while a longer ROM-02 measurement with an effect-appropriate stimulus remains useful.

Existing engine arithmetic, package validation, asynchronous loading, routing, and 5 ms effect switching are unchanged. Parameter state restoration uses SDK parameter chunks; the callback adds no parsing, file I/O, mutexes, vectors, or other dynamic allocation.

The candidate build runs the existing native HALL/ROM-02 backend and VST-wrapper audio tests, compiles native, ARMv7 hard-float, and ARM64 variants, generates the skin/Q-Link files with the SDK, and validates the package.
